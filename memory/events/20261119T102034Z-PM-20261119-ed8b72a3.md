On 2026-11-18 the run master decided that the Tauri desktop verifier never reads or writes the Windows system clipboard. Review threads on PR #186 showed that any save and restore of the clipboard can lose the human's data. An empty clipboard has no owner, a read was not bounded by the block size, and a text-only restore destroys non-text formats. The app now builds one function, destination, in two ways (apps/modn-desktop/src/app/commands/library.rs). A build with the verification feature writes the doctor report to the file named by MODN_VERIFY_CLIPBOARD_FILE and fails with CLIPBOARD_FAILED when the variable is unset or the write fails. A release build writes the system clipboard as before. The play journey deletes that file, activates Copy diagnostics, and requires the toast Diagnostics copied. and a doctor report in the file. The verifier refuses an app binary without the string MODN_VERIFY_CLIPBOARD_FILE, because that string exists only in a verification build. A selftest scan rejects every clipboard API in the verifier scripts. Do not add clipboard snapshot or restore code to the verifier again.
