An in-process unit test set the process environment variable MODN_TEST_GIT_FETCH_PROGRAM to a sh stub. Cargo runs lib tests on parallel threads, so other tests that ran git picked up the stub. Windows cannot run a shell script as a program, so buckets::git::tests::unsigned_later_revision_is_refused_and_preserves_the_published_copy failed in four of four runs. Commit 6346c00 fixed it with a thread-local override that only cfg(test) reads. The environment variable stays for CLI integration tests, because they set it on a child process only.
