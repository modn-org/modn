Implemented 2026-11-14 on the Milestone 8 run branch at 8c5324e. A package record pins its archive with blake3 (64 lowercase hex of the plain file bytes) and has no second digest. The optional upstream_sha256 is provenance only: Modn validates its shape and never compares it. The cache index, the cache entry names and the git packed ZIP digest use the tag blake3. A cache index that holds sha256 entries is ignored and rebuilt. The state database holds archive_blake3 in all four package tables, and managed_files and pending_files hold a per-file blake3 column (schema version 7). An earlier database is refused with a message and is neither read nor changed. Game-module release identity and bucket_digest::directory_digest also use BLAKE3, because issue #124 assumed per-file hashes were the last SHA-256 use and they were not. modn-core and modn-cli no longer list sha2 as a dependency. It still arrives transitively through the minisign crate and its scrypt dependency, and apps/modn-desktop keeps a direct sha2 dependency that the desktop run owns.
