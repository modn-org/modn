Milestone 16 moved the choice of release sources and cache keys, and the acquisition loop, from the CLI into modn-core.

Core now owns the plan. `plan_sources` orders the sources of a release (crates/modn-core/src/acquisition/plan.rs:77@e561b88). `source_cache_url` maps one `PackageSource` to its cache identity (plan.rs:22@e561b88). The GitHub release URL has one formatter. The planned order and the cache keys did not change, so a cache that 0.7.0 wrote still hits. Literal-key tests in core pin them.

Core owns the digest type. `ReleaseDigest` has three cases: a catalog BLAKE3 pin, a digest that Modn computed after a fetch, and not yet known (crates/modn-core/src/acquisition/release_digest.rs:56@e561b88). A `CacheKey` and a `CatalogDependency` cannot hold an empty digest. No `unwrap_or_default()` on a digest remains. One behavior fix came with this: an empty conflict digest used to equal a recorded empty digest. An unknown digest now matches no digest (crates/modn-core/src/transactions/conflicts.rs@e561b88).

Core owns the acquisition. `ArchiveCache::acquire_release` acquires a release through the `SourceTransport` seam and returns the archive path, the digest, the serving source and the ordered attempts (crates/modn-core/src/acquisition/release.rs:161@e561b88). The CLI passes in what it must keep through the `ReleaseResolver` trait (release.rs:40@e561b88): the HTTP transport, Nexus credentials and `nxm` links, the Git process, text notes and progress. `download_into` and the undo refetch call the same routine (apps/modn-cli/src/download/acquire.rs:55@e561b88).

Reason: one source of truth for order and keys removes three copies of the GitHub URL, and the acquisition tests now run in core with a fake transport. Known cost: undo HTTPS and GitHub refetch now follow the one extra transient retry of `acquire_from_sources`. Milestone 17 moves the install sequence; this milestone did not touch it.
