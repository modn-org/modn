`modn undo [<operation-id>] --yes` reverses one committed operation through the normal transactional install, update and uninstall paths. It is not a special writer. An undo of an install uninstalls the packages it installed; an undo of an update restores the release each package had before; an undo of an uninstall installs the removed release again from its recorded source, and the archive SHA-256 must equal the recorded one.

An undo writes a normal history record for its effect and sets the nullable `undoes` field to the target operation ID. Because that record is newer and touches the same files, the conflict rule needs no special case: undo refuses with `UNDO_CONFLICT`, before any change, when a later operation on the same installation touched a file or package the target touched. A second undo of the same target is refused the same way.

A target package with a `manual` source cannot be fetched again, so undo refuses with `UNDO_SOURCE_MANUAL` before any change. Other refusals are `UNDO_NOT_FOUND` and `UNDO_FAILED`. Known gap: undo of an uninstall for a Git or Nexus source is refused with `UNDO_FAILED`, because `acquire_source` in apps/modn-cli/src/download.rs fetches only `https` and `github-release` sources; Nexus needs a fresh nxm link. A multi-package record is undone all or nothing in one stack or one multi-package removal. Undo reports progress and accepts a stdin `cancel` before its commit point.
