As of 00a54bd (2026-11-12), Modn stores operation history in `state.sqlite` in four additive tables: `history_operations`, `history_packages`, `history_files` and `managed_package_releases`. They are created with the same guarded `CREATE TABLE IF NOT EXISTS` style as the rest of the schema, so the manager schema version stays 4 and older state opens unchanged. A read-only open never creates them.

A history record is inserted in the same SQLite transaction that commits the ownership change. An install or update inserts it with the new package; an uninstall inserts it with the ownership delete; a stack install inserts one record for all members when it finalizes the stack. A cancelled, refused, dry-run or rolled-back operation writes no record, and a failed history write rolls the ownership change back. History therefore never disagrees with ownership.

Each package row stores the package IDs before and after, the release version and the source descriptor (the bucket manifest shape: `manual`, `https`, `github-release`, `nexus` or `git`), the archive SHA-256 and BLAKE3, and each owned file with its SHA-256 before and after. The descriptor is stored in the record so undo needs no bucket snapshot. A package installed before these tables existed has no release metadata. History is evidence only; it grants no ownership authority.
