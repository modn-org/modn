Owner decision, 2026-11-08, for Milestone 5 (#51, #92, #93). Principle: a module is code Modn runs; trust belongs to the publisher's signer key and the user confirms it once. (1) Only signed Git catalogs can be trusted module sources; main is always trusted; local folder buckets cannot be module sources; local development keeps --module-src and module register --trust. (2) A module release is a required version in module.json plus a digest of module.json and module.lua, not a catalog revision. Update validates in staging and switches atomically; a failed update keeps the previous module; the same version with a different digest is refused; rollback switches to the previous version kept in the registry and changes only future plans, never installed files. (3) Trust covers the whole bucket, not one game: the owner rejected per-game trust because a trusted publisher can already change any of its modules. modn bucket trust-modules <bucket> shows the signer fingerprint and asks once; the trust record stores the signer key ID; a key change (#122) or untrust-modules ends it; a new game's module in a trusted bucket is reported at sync without a new acknowledgement. Official main modules keep priority with no override; doctor reports hidden third-party modules; untrusted buckets' modules are ignored at sync and refused at use. (4) New rule for docs/vision.md, docs/game-modules.md and AGENTS.md (owner approved the AGENTS.md change, to land with the implementation): main and the signed catalogs the user trusts for modules may contain game modules; Modn ignores modules from other buckets. No backward compatibility: unversioned registered modules must be registered again. Milestone 7 packs carry third-party modules only as references to a trusted source and pinned version.
