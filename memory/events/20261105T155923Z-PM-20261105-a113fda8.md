Use an optional `min_modn_version` field in `module.json`, compared with SemVer precedence against the `modn-core` build version. Keep host API v1.

Evidence, observed on 2026-11-05 against tag v0.2.0 (modn-org/modn@965f3f8), with a built CLI and a probe module:

- A module with `"min_modn_version": "0.3.0"` exits 1: `error: invalid module.json manifest: unknown field `min_modn_version`, expected one of `game_id`, `version`, `api_version`, `entrypoint` at line 1 column 101`.
- A module with `"api_version": 2` exits 1: `error: incompatible host API: module requires 2, host supports 1`.

Both paths refuse v0.2.0. The API error does not name a Modn release, and a bump would falsely change the Lua API contract. The new field alone refuses v0.2.0 safely. New clients name the required and running releases before Lua executes (`crates/modn-core/tests/module_min_version.rs`, modn-org/modn PR #103).

The Cyberpunk module declares 0.3.0 in modn-org/main PR #4. The workspace was 0.2.0 on 2026-11-05, so development builds refuse that module until the 0.3.0 release (#87).
