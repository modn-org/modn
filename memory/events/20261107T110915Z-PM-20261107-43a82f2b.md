Package manifests may set `native_injector: true` when a release places a native library that the game process loads. The field defaults to `false`, and non-boolean values are malformed.

Catalog install, stack and update entry points take `NativeInjectorPolicy::{Refuse, Allow}`; non-CLI callers pass `Refuse`. The CLI exposes `--allow-native-injector` on `install` and `update`. Without it, a plan that includes a native injector, including a missing dependency, fails with `NATIVE_INJECTOR_NOT_ALLOWED` before archive, consent, download or write work. `install --dry-run` refuses identically; `uninstall` needs no flag. An already-installed native dependency does not require the flag again.

JSON mode prints `{"error":"NATIVE_INJECTOR_NOT_ALLOWED","package":"<reference>","flag":"--allow-native-injector"}`. The refusal is enforced in the CLI before generic errors and again in the core transaction entry points.
