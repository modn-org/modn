Issue 190 reverses the removal recorded in pull request 185 round 6, with a different design. Every Modn Git fetch and clone runs in its own process tree: a Windows job object with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE (suspended start, assign, resume) or a Unix process group that Git leads. A guard value owns the tree for one run and stops it in Drop. There is no global fetch registry and no signal-hook thread. A hard deadline of 15 minutes, a cancel, and every Git exit stop the tree and confirm that no descendant is alive. If Modn cannot confirm, it returns GIT_PROCESS_TREE_NOT_STOPPED, the source and mirror loops stop without trying another candidate, and the staging directory stays. Ctrl-C cancels one process-wide interrupt token through the ctrlc crate and ends in the same tree stop. Git's own low-speed limits still apply. This was true at commit f1d151a.
