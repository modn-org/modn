Decision, 2026-11-28, on PR #239 (Milestone 20 branch) after `crates/modn-core/src/transactions/install/execute.rs:97@bf4ce5a` landed. An install refuses a second install of an archive the game installation already holds, with `ALREADY_INSTALLED` and the message "the archive <blake3> is already installed; uninstall it before installing it again". Only a different package may take over a managed path by profile priority; the identical archive may not install twice.

Reason: `Store::installed_archive` is checked in the locked install beside the catalog guard from 7a7bf92 ("Refuse a catalog reinstall of a release that is already installed."). Without it, the override contract let the same archive install twice and leave two packages with a shadowed claim. That broke the shipped CI gate `.agents/skills/verify-modn/scripts/verify.py` step `duplicate-install-blocked`, which failed on GitHub Actions job "rust (ubuntu-latest)" for run 46133257621 with "FAIL: duplicate-install-blocked: unexpected exit 0".

Evidence: `crates/modn-core/src/transactions/claim.rs:193@bf4ce5a` is the digest lookup. Three tests had adapted to the permitted duplicate in 1809a08: `apps/modn-cli/tests/framework_cli.rs` and `apps/modn-cli/tests/sevenz_cli.rs` were restored to their main content, and `crates/modn-core/src/transactions/generic_tests.rs` gained a second archive for the overlap case. Gates on bf4ce5a: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`, `cargo test --workspace --locked` and `python .agents/skills/verify-modn/scripts/verify.py --build` all pass.
