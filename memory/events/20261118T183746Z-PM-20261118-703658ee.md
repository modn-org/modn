Found 2026-11-18 by the Opus security review of PR 185 at 9fed850. The pin kept only the last applied rotation digest. After a rotation A to B and a rotation B to A, a holder of the retired key B could republish the first statement and move the pin back to B. Fixed at c36b359 (merged in c8f0f2b): Modn applies each rotation or revocation statement once and refuses a revision that republishes an applied statement for the pinned key. Test: a_replayed_rotation_cannot_roll_the_pin_back_to_a_retired_key. Known limit: rotation_statement writes the same bytes for a given key pair, so a legitimate repeated A to B after A to B to A matches the first digest and is refused. It fails closed.
