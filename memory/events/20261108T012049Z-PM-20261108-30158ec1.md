Decided 2026-11-07 by the owner, not implemented at 1eb4221. Issue #90 signs main releases and community Git catalogs over a canonical BLAKE3 digest of the catalog contents, not over a release ZIP or a Git commit. The same signature then works over Git, a catalog ZIP over HTTPS (#119), relocation (#120) and lookup by key (#125); Git SSH signatures would work only for Git. The format is minisign (Ed25519): Modn writes a canonical digest statement, the stock minisign CLI signs it, and Modn verifies with the pure-Rust minisign-verify crate. The main signer public key ships with the installer, and the main signature replaces the main-bucket.zip.sha256 sidecar. Each community Git catalog pins its signer key at first sync, and Modn shows the minisign key ID as its fingerprint. Modn always refuses unsigned or invalid main releases and Git catalog revisions; there is no --allow-unsigned override. Local folder buckets registered with 'bucket add <name> <path>' need no signature. Pre-alpha: no migration path. Key rotation and revocation are #122.
