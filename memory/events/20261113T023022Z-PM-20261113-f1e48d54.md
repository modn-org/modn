As of 2f4b01a (2026-11-13), Modn stores one approval per catalog mod, bucket and game installation, keyed by `(game_path, bucket, mod_id)`, in the `mod_approvals` table (manager schema version 5). It records whether native code is approved and the set of approved game-relative executable paths. An approval for a mod of one bucket never covers a same-named mod of another bucket, so a different publisher's native code or executable needs its own approval.

The rules of the earlier record hold. `--allow-native-injector` and `--allow-executable` still exist. An install or update whose release capabilities the stored approval does not cover is refused with `NATIVE_INJECTOR_NOT_ALLOWED` or `APPROVAL_REQUIRED`. A committed install or update stores or widens the approval, a later release that the approval covers needs no flag, and a release that adds a capability asks again. A cancelled, refused, dry-run or rolled-back operation stores nothing, uninstall keeps the approval, and a release that drops a capability does not shrink it. Explicit executable flags are kept apart from the stored declared capabilities and are not stored as an approval. Only the CLI backend writes approvals, and there is no revoke command.

A schema version 5 state file written before this change has an approvals table without the bucket column. A writable open rebuilds the table in the new shape and discards the old rows, so the user is asked again; a read-only open writes nothing. This was cheap because schema version 5 had not been released.

Known gap, unchanged: the approval is written in a second SQLite transaction after the install or update commits. If that write fails, the mod stays installed and the approval is not stored, and a repeat of the same command does not repair it. The gap fails closed. Moving the approval into the install transaction is a follow-up.

This supersedes the key description of PM-20261112-6eef7fee, which keyed approvals by game path and mod ID only. The maintainer decided on 2026-11-13, after review findings on #172, to add the bucket.
