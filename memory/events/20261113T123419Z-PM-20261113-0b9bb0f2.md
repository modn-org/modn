Modn 0.6.0 (2026-11-13, tag v0.6.0 on 63a86e4) and the `main` bucket release v2026.11.13 (tag on a9899c9, published 2026-11-13T12:33Z) are published, so the release order of PM-20261111-80d94a6a is met: the bucket release that declares `stores` and `launch` followed the Modn release that reads them. Store detection (`modn game detect`) and launch (`modn play`) read the new module data from this bucket release on.

The release workflows passed: Modn `build`, `smoke` and `release`, and the bucket `validate` and `release` jobs. The bucket release is signed with the key built into Modn. `.github/modn-ref` in modn-org/main pins the v0.6.0 commit, 63a86e4. Evidence from a throwaway data directory with the published 0.6.0 `modn.exe`: `modn bucket update` printed `Verified main bucket signed by 0E250AD52A3BA2AA` and installed the release, and `modn search cet` lists the Cyberpunk mod. `modn module check` accepts both modules.

modn-org/main#8 needed a code-owner review under branch protection and was merged with the admin override on the maintainer's instruction, as #7 was. Modn 0.5.0 refuses these modules ("unknown field `stores`"), so users on 0.5.0 must upgrade after `modn bucket update`. Not verified: detection and launch on a real Steam, GOG or Epic library, and opening a store URI; the maintainer tries them on a real machine.
