As of a1916a7 (2026-11-11), `install`, `update` and `uninstall` accept `--progress json`. Each event is one JSON object per line on stderr, so stdout stays unchanged. Phases in order: `resolve`, `download` (`package`, `bytes`, `total` or null), `extract`, `stage`, `commit` (the commit point), `result` (`outcome` succeeded|failed|cancelled, `error` code when not succeeded). A stack install reports one download-to-commit group per package.

A `cancel` line on stdin cancels before the commit point with `CANCELLED` and leaves game files, manager state, ownership and cache unchanged. From the commit point on, cancel is ignored. The core API is `OperationControl`, `CancellationToken` and `ProgressEvent` in `crates/modn-core/src/progress.rs`.

Every user-visible error carries a stable code from the closed `ErrorCode` enum in `crates/modn-core/src/error.rs`, attached with `coded`/`with_code` and read with `code_of`. A "CODE:" message prefix is not a code. A command without a more specific code falls back to its per-command default, such as `INSTALL_FAILED` or `PLAY_FAILED`. The list is in docs/cli.md "Error codes"; a completeness test keeps the enum and the list equal. The MCP server maps these events to `notifications/progress` and cancels through the same stdin line.
