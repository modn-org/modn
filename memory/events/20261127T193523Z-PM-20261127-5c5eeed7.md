Milestone 19 closed on 2026-11-27 after PR #237 merged into main as 654f202. Issues #200, #201, #202, #203 and #187 closed through the PR.

Exit gate at 654f202 (tree identical to the PR head caf68ae):
- `catalog_checkver_update_cli`: `checkver_update_rewrites_a_github_release_and_keeps_unrelated_bytes` and `checkver_update_rewrites_a_git_commit_and_version` update version, source and BLAKE3 pin against mocked endpoints. `--update` never touches `catalog.sig` or a key.
- `catalog_init_cli`: `scaffold_keygen_sign_verify_and_register_as_a_local_bucket` signs and registers the scaffold. `sample_template_becomes_a_package_that_search_and_dry_run_resolve` runs the validation steps of `validate.yml`. `workflows_run_only_reviewed_commands_and_autoupdate_never_signs` checks both workflows. No test runs the workflows on GitHub Actions.
- `known_buckets_cli`: `known_sync_refuses_a_fingerprint_mismatch_without_writing_state` refuses a mismatch with `BUCKET_FINGERPRINT_MISMATCH`.
- These three suites pass 20 tests with Rust 1.100.0. `cargo test --workspace --locked` passes 1982 tests on caf68ae. CI passed on Ubuntu and Windows.

Signed sequence numbers (#187): the highest accepted `{sequence, digest}` lives in the bucket registration files under the profile, not in `state.sqlite`. `modn bucket update` records it for `main` before the swap, so an interrupted update leaves the record ahead and refuses only older catalogs. `update_sequence_tests.rs` proves this with an injected swap failure.

Review: one review (head 3b551f1) found that a numbered catalog could not deliver a key rotation. bdda0ce fixed it; the fix was not re-reviewed. The advisory finding (record written after the swap) was fixed in caf68ae. Not reviewed: the checkver GitHub and Nexus parsers, the glob matcher and `manifest_edit` internals.

Known limits: `checkver --update` does not support Nexus sources. A registration file with an `accepted` field is refused by older Modn builds.
