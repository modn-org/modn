Verified on 2026-11-26 against docs/history.md and apps/modn-cli/tests/undo_cli.rs at b51e6eb. Install and update history records the serving source that supplied the archive, not the first source in the release list, so undo looks up the cached archive under that source. A user-supplied --file archive whose BLAKE3 digest matches the catalog pin is recorded with the release's first https or github-release source so undo can restore it; only a release with no refetchable source (or a standalone archive) stays manual, for which undo restore returns UNDO_SOURCE_MANUAL. Removing a --file install via undo still works because removal needs no archive. Supersedes PM-20261118-e513586e, which stated that all --file installs were recorded as manual.
