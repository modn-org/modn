Implemented 2026-11-27 on the Milestone 19 run branch (merges 7c04708, 3b551f1, bdda0ce). A numbered catalog has a root sequence.json {schema_version, sequence, expires?} that the existing catalog digest covers, so catalog.sig, modn-catalog-signature/v1 and released main v2026.11.24 stay valid. Modn stores the highest accepted {sequence, digest} as an optional accepted field in the registration file under the manager profile, and in <profile>/buckets/main.json for main, which has no registration. state.sqlite is untouched because Milestone 20 owns that schema. Rule: unnumbered is accepted until a number was accepted; after that a lower or dropped number is CATALOG_ROLLBACK and the same number with another digest is CATALOG_SEQUENCE_CONFLICT; a first sync always works; a passed expiry only warns. A key statement must equal the revision sequence only when it moves the pin; history keeps its signed number. In a numbered catalog rotate and revoke name file+1 and sign treats that number as a floor. Known limits: an older Modn build with deny_unknown_fields refuses a registration file that has accepted; update.rs writes main.json after the swap, so a failure between them leaves the rollback check open (advisory review finding at crates/modn-core/src/buckets/update.rs:213@3b551f1). Recovery: bucket remove then re-add clears the stored number.
