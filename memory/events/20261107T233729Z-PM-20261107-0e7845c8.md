Decided 2026-11-07, not implemented at 794cd8d: bucket contract v2 (#117) replaces the SHA-256 archive pin with a BLAKE3 pin and keeps no second digest.

Rationale: one value serves as the manifest pin, the cache and digest-index key (#91), the iroh-blobs hash (#115) and the seeder lookup key (#130). The iroh-blobs root hash is the plain BLAKE3 hash of the file bytes, so each streamed chunk is checked against the trusted pin from the signed record. With two digests, a peer could map a SHA-256 to a wrong BLAKE3 hash, and Modn would detect it only after the full download.

An upstream SHA-256, when known, is provenance only. Per-file hashes in managed_files and pending_files stay SHA-256 until #124. Pack lockfiles use BLAKE3 (#112).
