Adding a package to the official main bucket now means adding one manifest JSON and one PROVENANCE row. crates/modn-core/build.rs generates the include_str! list from buckets/main/games, and the catalog and gate tests derive their package lists from the same directory.

Before this, store.rs listed every manifest with include_str! and three test files hardcoded package ids, counts and a dependency table, so a new package touched four Rust files. The build script needs no new dependency and reruns when the directory changes. Trade-off: the milestone gate no longer pins each package's version and dependencies in a separate table, so a manifest edit no longer fails a test until someone updates that table. The ignored live-archive gate still pins the owned-file count (147), because it measures real archives. A non-JSON file in the official directory now fails the build. Verified by dropping a throwaway manifest into the directory with no Rust edits: it appeared in `modn search` and the catalog, bucket and gate tests passed.
