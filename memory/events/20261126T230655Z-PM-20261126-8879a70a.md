Decided 2026-11-26 for Milestone 14 "Module selection and trust" (issues #162, #163, #164, #165, #166), implemented in this PR stack and not yet merged.

One function decides module-source trust: `decide_module_source_trust` in `crates/modn-core/src/buckets/trust_decision.rs`, reached through `BucketStore::module_source_trust`. A module release is trusted only when its recorded signer is authorized by the signer that the bucket's trust record currently names. `main` is always trusted. A local folder bucket is never a module source. A release with no bucket (a local registration) is trusted. A signer change ends trust until the release is signed by the trusted signer. The resolver, `modn module list`, `modn module update` and the doctor diagnostics all read this decision. Before this change `modn module list` ignored the recorded signer and could print `source_trusted: true` for a release that policy refused; `apps/modn-cli/tests/module_signer_change_cli.rs` pins the agreement.

One `ModuleSelection` (`crates/modn-core/src/game_modules/selection.rs`) holds the governing module per command: origin, verified module and trust decision. Precedence: development override, then the official `main` module, then a retained release from the module registry; otherwise an explicit refusal, with no fall-through after a refusal. Core no longer reads `MODN_GAME_MODULES_DIR`; the CLI reads it and passes the override. Module bytes are verified again at each execution boundary; the selection is not a cache.
