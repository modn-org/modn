On 2026-11-07 the owner amended issue #90 and then settled its open points. A signature covers a canonical BLAKE3 digest of the catalog contents, not a release ZIP or a Git commit, so one signature works over Git, HTTPS catalog ZIPs (#119) and later transports. The format is minisign (Ed25519): Modn writes a canonical digest statement, the stock minisign CLI signs it, and Modn verifies it with the pure-Rust minisign-verify crate. The main signer public key ships with the installer, and the main signature replaces the main-bucket.zip.sha256 sidecar. Each community Git catalog pins its signer key at first sync, and Modn shows the minisign key ID as the fingerprint. Modn always refuses unsigned or invalid main releases and Git catalog revisions; there is no --allow-unsigned override. Local folder buckets registered with 'bucket add <name> <path>' need no signature, because they are the user's own files. Modn is pre-alpha, so there is no migration path; old formats are refused with a clear message. Key rotation and revocation are deferred to #122.
