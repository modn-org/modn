insert_destination and commit_install key paths with str::to_lowercase, which maps a word-final capital sigma to final sigma; NTFS maps it to medial sigma. So archive/pc/modΣ/x.archive and archive/pc/modσ/x.archive are one NTFS file with two Modn keys. A dry run proposing both reports reviewable; install --yes then fails with 'existing unmanaged destination' and rolls back. No data loss was observed.

An exhaustive BMP scan on Windows 11 NTFS found 973 one-character spellings that name one file. to_lowercase disagreed only on this sigma pair at a word end; per-character to_uppercase (case_key) disagreed on none. Cross-package collisions are currently caught on disk by existing_destination_issue (ALIASED_DESTINATION or EXISTING_FILE). A fix must also migrate stored path_key values. Checked by same_file_spellings_share_one_ownership_key and reviewable_dry_run_predicts_the_install, both #[ignore] until fixed.
