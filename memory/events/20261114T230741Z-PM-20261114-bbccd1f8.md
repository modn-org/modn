Implemented 2026-11-14 on the Milestone 8 part 2 branch at 0b5f410. A signed catalog may hold mirrors.json (up to 8 sources, git or https ZIP, no credentials or local paths) and relocation.json (one new primary). Both sit in the signed content, so the existing digest covers them. Sync tries the registered primary, then the stored mirrors. A transport failure (timeout, network, HTTP, malformed ZIP) moves to the next source. A signature or key failure (another key, tampered, unsigned, digest mismatch) stops the sync and never falls through to a mirror. One relocation is followed per sync, and the registration changes last. A ZIP catalog is a signed catalog directory zipped, verified in staging before publication; an absolute local ZIP path is also accepted so the CLI can be tested without a server. Relocation and mirror targets must be https, so offline fixtures prove only the recorded move.
