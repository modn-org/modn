The official main bucket moved from buckets/main to the public modn-org/main repository, with its 17-commit history (git subtree split). `modn bucket update` fetches main-bucket.zip and its .sha256 from the latest modn-org/main release. Modn releases no longer publish main-bucket.zip. modn pins a bucket commit as the buckets/main submodule for its tests, smoke tests and verify-modn. The bucket CI builds the modn revision in .github/modn-ref, packs only bucket.json, PROVENANCE.md and games/, and runs bucket update and search against the ZIP. A v* tag publishes the validated ZIP. The bucket repository forces LF, so the ZIP bytes do not depend on the platform.

Constraints found on 2026-11-04: modn-org is on the free plan and modn-org/modn is private, so branch protection there returns HTTP 403, and modn-org/main CI cannot check out modn until modn is public. The only modn release, v0.1.0, has no `modn bucket update`, so the bucket CI pins a modn commit (c5ce1ad) instead of a release. Change .github/modn-ref to a release tag once a release includes bucket update. The host API rule already holds: validate_manifest rejects an api_version other than HOST_API_VERSION before the swap. bucket_update_cli now pins that rule.
