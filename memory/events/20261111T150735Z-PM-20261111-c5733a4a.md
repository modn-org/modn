As of a1916a7 (2026-11-11), a game module declares its store identities as data in an optional `module.json` `stores` object, never in Lua. Keys: `steam` (app ID, 1 to 10 digits), `gog` (product ID, 1 to 20 digits), `epic` (Epic Games Launcher `AppName`). An unknown key or a malformed identity makes the module invalid with `MODULE_STORE_ID_INVALID`.

Rust reads the Steam, GOG and Epic libraries on Windows and knows store formats, not games. A library only proposes a folder. The module's `validate` policy then confirms it with that folder as the only readable root, the same check as `game add --path`. `modn game detect` writes nothing; `--register` writes manager state only. Lua gets no new filesystem or process API.
