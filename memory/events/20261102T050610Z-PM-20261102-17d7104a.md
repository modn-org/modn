All Rust, Lua, Python and TOML comments were removed except keeps. modn-core keeps doc comments on public items that state a contract. Docs that only restate an item name were replaced by #[expect(missing_docs, reason = ...)] on the parent. Constraints from deleted comments are covered by tests.

Keeps: platform and dependency gotchas (NTFS case folding, 8.3 names, MoveFileEx, inode reuse, Windows verbatim paths, 7z solid blocks, ZipWriter and ZipArchive duplicate names) and the clap help doc comments in apps/modn-cli/src/commands.rs, which are help text. crates/modn-core/src/lib.rs keeps #![warn(missing_docs)] and CI runs clippy with -D warnings, so public items need a doc or an expect. Audit of 48 'never/must/only' claims from deleted comments: most already had tests. Four tests were added: host_answers_carry_no_host_path_or_handle (read_only_capabilities.rs), linked_state_root_cannot_redirect_registration_writes (buckets_cli.rs), unregistering_a_game_ends_its_directory_records (created_dirs_tests.rs), absent_or_replaced_owned_directory_refuses_uninstall_without_a_journal (generic_tests/directories.rs). Each was shown to fail when the guarded code was broken. Not encoded: the Lua proxy rawset caveat in runtime.rs (a non-guarantee; a test would freeze a weakness), 'registered paths are not canonicalized' in buckets.rs, and 'check conflicts before any download' in catalog_install.rs, which the current code does not do when --download is set.

Supersession reason: The claimed constraints that lost their comments now have tests, except the two listed in the body.
