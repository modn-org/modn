Implemented on the Milestone 4 run branch at a7d1fd0 (2026-11-08), not yet released. Main bucket: the owner generated a minisign key pair; its public key (key ID 0E250AD52A3BA2AA) is embedded in the modn binary from apps/modn-cli/src/main-bucket.pub, so it ships with the installer. The owner keeps the secret key and its password; they go into modn-org/main as GitHub Actions secrets so the bucket CI can sign each release (bucket CI signing not done at a7d1fd0). Each main release must carry main-bucket.zip.minisig; the SHA-256 sidecar is gone. Replacing the key means replacing that one file and shipping a new Modn build. Git catalogs: trust on first use. The first 'bucket sync' takes the key from the catalog's root catalog.pub, pins key ID and public key in the registration, and prints the fingerprint for out-of-band comparison; later revisions verify with the pinned key only, and a changed key is refused until the user removes and re-syncs the bucket. Local folder buckets are unsigned. Rotation and revocation are #122. Test builds accept MODN_TEST_MAIN_BUCKET_PUBLIC_KEY only with the modn-core feature test-main-key, which only modn-cli dev-dependencies enable.
