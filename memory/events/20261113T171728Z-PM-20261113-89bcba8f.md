On 2026-11-13 the owner decided that, from Milestone 6 phase B on, the HTML and CSS code of the Tauri desktop app (#142) is the source of truth for screen layout and behaviour. design/design.figcraft stays the home of the owner's design system: variables (tokens), text styles and the Foundations and Components pages. The CSS takes its values from those tokens as var(--modn-<group>-<name>). The Milestone 6 screen pages from PR #181 (Home, Library, Mod details and their state frames) are a reference spec for which states each screen needs. Nobody keeps them in sync with the code, and phase B starts no new mockup pass.

Reason: the run that produced PR #181 needed four fix rounds after its one review. PR bots cannot review a binary .figcraft file, so most bot findings were about documents and memory records, not screens. Only the owner, looking at the canvas, found the frame overlaps and the unequal mod-tile heights. In code each change is a reviewable diff, CSS grid gives equal-height tiles directly, and the desktop verifier of #142 can test the real screen.

Known defects left in the PR #181 mockups, to decide in phase B code review: mod-tile heights differ in the native-code ask state; the Library "Installed" tab shows not-installed mods; the search label has too little contrast; Allow and Decline align right while the tile content aligns left; the three-column grid leaves an empty column; no warning colour token exists, so the warning badge uses modn/color/text; modn/color/primary stays teal until the owner picks from the candidates collection.
