Modn stores one approval per catalog mod and game installation, keyed by `(game_path, mod_id)`, in the `mod_approvals` table (manager schema version 5). It records whether native code is approved and the set of approved game-relative executable paths.

This supersedes the per-command opt-in rule in PM-20261107-43a82f2b in part. `--allow-native-injector` and `--allow-executable` still exist, and an install or update whose release capabilities the stored approval does not cover is still refused with `NATIVE_INJECTOR_NOT_ALLOWED` or `APPROVAL_REQUIRED`. The difference is that a committed install or update stores or widens the approval, so a later release the approval covers needs no flag. A release that adds a capability asks again. A cancelled, refused, dry-run or rolled-back operation stores nothing; uninstall keeps the approval; a release that drops a capability does not shrink it.

Only the CLI backend writes approvals; MCP and desktop inherit the stored decision. There is no revoke command. Known gap: an install commit followed by a failed approval write leaves the mod installed with the approval unstored; a rerun with the flag repairs it.
