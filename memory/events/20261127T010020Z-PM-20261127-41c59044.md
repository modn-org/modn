Milestone 14 closed on 2026-11-26 after PRs #227, #228, #229, #230 and #231 merged bottom-up into main. The last merge is e8616d0. Issues #162, #163, #164, #165 and #166 closed through the PRs.

Exit gate at e8616d0:
- One function decides module-source trust: `decide_module_source_trust` in `crates/modn-core/src/buckets/trust_decision.rs`. `BucketStore::module_source_trust`, `ModuleSelection`, `modn doctor`, `modn module list` and `modn module update` all use it.
- `cargo test -p modn-core --locked --test module_source_trust --test module_selection`: 6 tests pass. `module_source_trust_table` covers the (trust record, pinned signer, release source) cases. `module_selection_table` covers the governing-module precedence: development override, official `main`, then a trusted retained release.
- `cargo test -p modn-cli --locked --test module_signer_change_cli --test module_update_signer_cli`: 5 tests pass. `module_list_and_policy_agree_after_a_catalog_signer_change` shows that `modn module list` and policy resolution agree after a signer change.
- `cargo test --workspace --locked`: 1757 tests pass. CI passed on Ubuntu and Windows for every PR in the stack.

Refusal messages (commit 5171c71): after a signer change, or when the release signer is unauthorized, revoked or missing, the refusal and the `modn module list` warning tell the user to run `modn module remove <game>` first, then `modn bucket trust-modules <bucket>`. An unregistered bucket never gets a `trust-modules` suggestion.

The local gate run needs the `buckets/main` submodule. Without it, `module_selection_table` fails with "cannot load local main bucket".
