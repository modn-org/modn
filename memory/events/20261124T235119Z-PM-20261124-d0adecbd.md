Modn selects the newest non-draft, non-prerelease `modn-org/main` release whose `main-bucket.requires.json` declares the supported `schema_version` (2) and a `min_modn_version` less than or equal to `env!("CARGO_PKG_VERSION")` under SemVer precedence. A release without the asset remains legacy-readable. A malformed requirements file skips that release with a diagnostic; a read failure fails the update. The selected release's listed `main-bucket.zip` and `main-bucket.zip.minisig` URLs use the existing `BucketStore::update_main` verification and atomic install path. `MODN_MAIN_BUCKET_SOURCE` bypasses selection. Output reports the selected release and `newer_release_needs_modn`. If no release is supported, the installed bucket stays unchanged. `MODN_TEST_MAIN_BUCKET_RELEASES` is compiled only with the `test-main-bucket-releases` feature, enabled by `modn-cli` dev-dependencies.
