Found 2026-11-14 by the independent review of Milestone 8 part 2 (no blocking finding). Advisory: Modn compares no revision identity or freshness, so a stale mirror can serve an older revision that the pinned key signed (and an older relocation.json). A user who skipped a rotation cannot catch up through one revocation because a statement must name the pinned key exactly. A catalog with revocation.json on record refuses a later rotation as both statements. modn catalog sign checks only the key file it uses, so another secret key inside the directory would be signed and published. The exit-gate sentence about installing from the second origin is proven at the core seam, not through modn install. Follow-ups, not part of this change.
