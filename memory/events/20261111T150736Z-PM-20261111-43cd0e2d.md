As of a1916a7 (2026-11-11), a game module declares launch targets as data in an optional `module.json` `launch` object: `steam` (`steam://rungameid/<id>`, equal to `stores.steam`), `gog` (`goggalaxy:` URI, needs `stores.gog`), `epic` (`com.epicgames.launcher:` URI, needs `stores.epic`), and `executable` (a normalized game-relative `.exe`). Rust validates every target; an invalid one makes the module invalid with `MODULE_LAUNCH_TARGET_INVALID`. At launch Rust canonicalizes the executable below the installation and refuses an escape with `LAUNCH_TARGET_UNSAFE`.

`modn play` prefers the store URI when detection shows the folder came from that store, and otherwise starts the executable in the game folder. It refuses while a recovery is pending and warns when managed files changed outside Modn. Lua never receives launch targets. Unverified as of this date: the GOG and Epic URI formats (the shipped modules use the executable fallback there) and URI opening, which has no automated test.
