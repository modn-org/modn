On 2026-11-09 the owner approved this design workflow. Each desktop page has one canonical design file, design/pages/<page>.figcraft, that the agent edits on request. The owner owns design/design-system.figcraft, a FigCraft library of tokens and components, and every publish of it. Pages take tokens and components from that library. The agent drives the owner's running FigCraft app through figcraft-cli mcp --attach, so the owner watches each change. When a request conflicts with the design system, the agent stops and asks whether the owner changes the design system or approves a page-only override. Files and the skill live in the repository. The format is .figcraft, because library.add accepts only .figcraft and FigCraft 0.17.0 calls its .fig output experimental. Tokens named modn/<group>/<name> export from inspect.code as var(--modn-<group>-<name>), matching the --modn-* theme properties of #142. Evidence: a live run of the skill against FigCraft 0.17.0 passed 24 checks on 2026-11-09, including an owner publish pulled with library.acceptUpdates and an instance override kept through it. The Steam library concept from the earlier FigCraft trial copied the Steam look; PM-20261109-342eac2a keeps Workshop interactions without that look.
