Implemented 2026-11-27 (merges 7034c9d, b76894f, 9b38f72, 8fa8754). The optional checkver block (kinds github-release, git, nexus) is read only by modn catalog checkver; user commands ignore it. checkver <dir> [mod-id] [--json] reports up_to_date, update_available, skipped or error and exits nonzero when any package errored. --update downloads to a temp file, hashes with BLAKE3, rewrites the manifest atomically keeping key order and indentation, clears upstream_sha256, and requires the checkver repository to equal a source repository; --keep-previous saves <id>@<old>.json; nexus update is unsupported because Nexus downloads need the user's own authorization. The command never touches catalog.sig or keys and reminds the maintainer to run catalog sign and verify. Tests redirect upstream endpoints through the test-checkver-endpoints feature, enabled only by modn-cli dev-dependencies. modn catalog init scaffolds validate.yml and autoupdate.yml; autoupdate opens a pull request from a new branch and never signs.
